# Elexto 项目架构说明

## 1. 实现目标

以 Pixso 的「Elexto - Music App UI Kit」为参考，使用 Flutter 原生 Widget 实现可维护的音乐 App。设计页为 `Elexto`，包含 36 组界面状态、每组 Dark / Light 两个版本，原始基准宽度 375。

运行时使用同一套组件切换两种主题。键盘由系统提供，长页面可以滚动，歌曲、收藏和歌单交互绑定实际状态，不将整页设计图用作页面背景。

## 2. 分层与依赖方向

```text
main.dart
   ↓ 初始化
PreferenceStore ← AppController ← AppScope
                      ↑               ↑
                 本地曲目目录     页面与共用组件
                      ↓
                 AudioPlayer
                      ↓
               iOS / Android / Web
```

| 层 | 文件位置 | 职责 |
| --- | --- | --- |
| 应用入口 | `lib/main.dart`, `lib/app.dart` | 初始化、本地数据恢复、路由、主题、状态栏样式 |
| 状态与能力 | `lib/core/app_controller.dart` | 当前曲目、播放状态、会话、收藏、关注、歌单及持久化协调 |
| 设计基础 | `lib/core/app_theme.dart` | 主题、配色、文本、按钮、进度条、提示消息样式 |
| 数据边界 | `lib/data/` | 曲目模型、静态目录与偏好存储适配 |
| 页面模块 | `lib/features/` | Auth、Music、Library 三个业务模块 |
| 共享视图 | `lib/widgets/ui.dart` | 图片、主按钮、纵向栏目、歌曲行、迷你播放器、进度与播放控制 |

页面通过 `AppScope.of(context)` 读取控制器，调用行为方法。控制器变更状态后通知界面刷新。页面内部的搜索词、当前标签和弹层显示状态留在对应 `StatefulWidget`，避免把短暂 UI 状态存入全局。

## 3. 播放数据流

1. 点击 `SongTile`，调用 `AppController.play(track)` 并打开播放器。
2. 控制器用 `AssetSource` 读取对应 `assets/audio/demo-N.wav`。
3. `AudioPlayer` 回传播放、时长和完成事件；每 250 毫秒读取一次实际播放进度。
4. 迷你播放器、完整播放器和视频海报预览共用同一个播放器实例。
5. 拖动进度调用 seek；完成后根据循环/随机设置重播或切换歌曲。
6. 离开页面不会创建第二个音频实例；退出登录会暂停播放，控制器销毁时取消订阅并释放播放器。

每段音频长 24 秒，因此实际播放器显示真实时长；设计稿里的 `3:12 / 5:43` 只在静态推荐封面上保留。

## 4. 本地存储

`PreferenceStore` 封装 `SharedPreferencesAsync`，提供 bool、String、StringList 三类读写接口。测试注入 `PreferenceStore.memory()`，避免污染用户数据。

| 数据 | 存储方式 |
| --- | --- |
| 主题、引导完成、演示登录状态、关注状态 | bool |
| 昵称、邮箱 | String |
| 收藏曲目 ID、离线预览 ID、均衡器五段数值 | StringList |
| 歌单名与曲目 ID 映射 | JSON String |
| 密码、验证码 | 不持久化 |
| 实时播放位置、搜索词、弹窗 | 内存状态 |

歌单加入操作去重。复制生成独立列表；重命名检查名称冲突；删除需确认；空歌单、空下载、未关注及无搜索结果均有可见反馈。

原稿将同一个页面的输入、键盘、展开、弹层、成功消息分成多个画板。应用通过可交互状态复用页面，避免维护 72 份重复代码。

| 6 | `/signup` | 注册、邮箱冲突提示、邀请码 |
| 7–8 | `/phone` | 手机号空/已填写状态及系统键盘 |
| 9 | `/forgot` | 重置验证入口 |

| 13–14 | `/home` | 纵向内容、专辑轮播、推荐、迷你播放器和底部导航 |

## 6. UI 与资源

设计色值集中在 `Palette`：背景 `#262345`、卡片 `#3B3577`、主色 `#FF5355`、粉色 `#E9BBD5`、浅色卡片 `#FFEFF8`。深浅模式通过 `ThemeData` 控制，共用业务组件。

大部分页面用 Column / Row / ListView 组织，图片叠层与播放器才使用 Stack。安全区域由 SafeArea 处理，输入页根据键盘压缩后的空间滚动。原稿超过一屏的画板保留内容并允许滚动。横向专辑和搜索标签可滚动或换行。

39 个素材以 2 倍图从 Pixso 图层导出，其中 `genre-1` 与 `genre-4` 复用了原稿同一照片。页面使用原始插画、封面与人物资源，共用图片组件统一圆角；不依赖临时 localhost 资源。原始设计参考图放在 `docs/design/`，不打包进应用。

## 7. 精简与后续扩展

- 不保留生成器的绝对定位页面、逐矢量组件、适配扩展及无用样式管理代码。
- 播放、存储两个功能依赖及一个原生图标字体包；不引入额外路由、状态管理、图表或网络框架。
- Auth 页面按模式复用；播放控制、歌曲行、纵向栏目、卡片和本地资源抽成共享组件。
- 偏好存储与界面隔离，便于后续替换为数据库或远程服务。
- 原稿界面按业务模块组织；未为轻量本地演示添加空 repository/use-case 层。

接入生产服务时，建议先抽出认证、音乐目录、下载和播放服务接口，再对接 API、错误状态与缓存。真实密码修改、短信、视频流、硬件均衡器与外部分享属于尚未接入的服务能力，详见 README 的演示范围。

## 8. 验证策略

单元测试验证状态保存、歌单去重与播放队列边界。Widget 测试验证登录校验、搜索过滤与空状态，并逐路由检查深浅主题的布局异常。原生集成测试验证实际音频能进入播放状态、进度推进、收藏、加入歌单、下载、关注、复制歌单、弹层及两种主题。
